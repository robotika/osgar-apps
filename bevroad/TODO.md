# BEV Road Mapping - TODO & Future Improvements

This document tracks planned optimizations, robustness enhancements, and features for transitioning the Bird's Eye View (BEV) road mapping prototype from a Proof of Concept (PoC) to a production-ready system.

## 1. Performance & Memory Optimization (`mosaic.py`)
- [ ] **Eliminate Full-Canvas Warping:** Currently, each frame is warped to the size of the entire global canvas (which can grow to thousands of pixels on each side), creating massive memory allocations and redundant pixel processing.
- [ ] **Combine Warp Matrices:** Combine the homography matrix $M_{\text{perspective}}$ and the 2D affine warp matrix $M_{\text{affine}}$ into a single combined perspective matrix:
  $$M_{\text{combined}} = M_{\text{affine}} \cdot M_{\text{perspective}}$$
  This avoids double-warping (and double-resampling pixel degradation).
- [ ] **Localized Patch Rendering:** 
  1. Calculate the local bounding box of the warped frame's corners *on the canvas*.
  2. Warp the original frame directly onto a small patch representing just that bounding box (using the combined matrix shifted by the bounding box offset).
  3. Copy/paste this small patch onto the global canvas using slice-indexing and a localized mask. This reduces the stitching overhead by **10x to 100x**.

## 2. Temporal & Spatial Precision (`log2imdir.py`)
- [ ] **Pose Time Interpolation:** Both the camera stream and `platform.pose2d` run at approximately 10Hz. For higher speeds or more precise positioning, implement temporal interpolation of the Pose2D coordinates based on the exact camera frame timestamps rather than relying on the nearest pose update.
- [ ] **Handle Distance Milestones Gracefully:** Ensure that when multiple distance milestones are crossed in a single pose update, only a single frame is written and the target distance is bumped correctly past the accumulated distance (preventing duplicate frame extractions at identical coordinates).

## 3. Resolution Independence
- [ ] **Track Source Image Dimensions:** Save `source_width` and `source_height` in the calibration JSON (e.g., `bev.json`) generated by `view_bev.py`.
- [ ] **Scale Homography Dynamically:** If frames processed in `mosaic.py` or `view_bev.py` have different dimensions from the calibration source image, scale the homography matrix using a resolution scale transformation matrix $S$:
  $$M_{\text{scaled}} = M_{\text{calib}} \cdot S^{-1}$$

## 4. Interactive Calibration Enhancements (`view_bev.py`)
- [ ] **Optimize GUI CPU Usage:** Avoid redrawing the calibration trapezoid and warping the image continuously every 30ms. Only recompute and update the display when trackbars are actually moved.
- [ ] **Collinear Point Error Handling:** Wrap `cv2.getPerspectiveTransform` in a `try...except cv2.error` block to prevent application crashes when users drag sliders into collinear or coincident configurations (e.g., setting top width to 0 or top Y equal to bottom Y).
- [ ] **Simplify Math:** Simplify the redundant expression `tx = cx + (offset_x - cx)` to `tx = offset_x`.

## 5. Robustness & Modularity
- [ ] **Refactor for Testability:** Extract coordinate transformations, bounds calculations, and control-point mapping math from the monolithic `main()` function in `mosaic.py` into testable helper functions. Unit-test these functions in `test_mosaic.py`.
- [ ] **Robust Video Codec Auto-Detection:** Implement a `--codec` CLI option in `log2imdir.py` as a fallback for cases where raw bitstream packet headers are not standard H.264/HEVC formats.
- [ ] **Input Validation:** Add validation checks to prevent divide-by-zero or negative bounds when user input for `--resolution`, `--lane-width-fraction`, or `--road-width` is invalid or out of range.
- [ ] **Deterministic Config Selection:** Print an explicit log message showing which configuration JSON file was loaded, and warn the user if multiple JSON files are found in the target directory.
